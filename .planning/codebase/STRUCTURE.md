## Top-Level Classification

Classification uses four primary labels:

- **Essential:** Source, tests, configuration, or maintained project documentation.
- **Generated/local-only:** Reconstructable machine state, build output, or checkout metadata.
- **Historical:** Audit/planning evidence retained for traceability, not imported by the runtime.
- **Simplifiable:** A non-authoritative anomaly or structure that can be made smaller or clearer without removing required behavior.

| --- | --- | --- |

| `.gitignore` | Essential | Defines build, environment, cache, coverage, and local-state exclusions. |

## Directory Purposes

**`src/openrund/`:**

- Purpose: Installable, typed runtime package.
- Contains: Public facade modules, package areas, `py.typed`, CLI, demonstration, common errors, and path values.
- Key files: `src/openrund/__init__.py`, `src/openrund/__main__.py`, `src/openrund/cli.py`, `src/openrund/errors.py`, `src/openrund/paths.py`.
- Subdirectories: Domain contracts, codecs, Views, Engine, ports, adapters, composition, and test substitutes.

**`tests/`:**

- Purpose: Prove domain invariants, deterministic replay, legality, durability, security boundaries, packaging, typing, docs, compatibility, and end-to-end flows.
- Contains: Pytest modules organized to mirror `src/openrund/`, plus package/release checks.
- Key files: `tests/conftest.py`, `tests/package/test_public_api.py`, `tests/package/test_release_hygiene.py`, `tests/docs/test_documentation.py`.
- Subdirectories: `assembly/`, `bundles/`, `capabilities/`, `cli/`, `codec/`, `contracts/`, `demo/`, `docs/`, `engine/`, `operator/`, `package/`, `ports/`, `providers/`, `runtime/`, `storage/`, `views/`, and `fixtures/`.

**`tests/fixtures/compatibility/v1/`:**

- Purpose: Frozen compatibility oracle for the Python cutover and future runtimes.
- Contains: `manifest.json` and 286 JSONL evidence files covering Events, decisions, Views, providers, SQLite schema, canonical numbers/escaping, rejection behavior, Bundles, and retirement evidence.
- Key files: `tests/fixtures/compatibility/v1/manifest.json` and `tests/fixtures/compatibility/v1/evidence/`.
- Treatment: Essential, immutable test input. Add a new versioned corpus rather than silently rewriting v1 semantics.

**`docs/`:**

- Purpose: Normative runtime contracts and maintained user/developer guidance.
- Contains: Markdown documents checked for links, API references, and current Python-only instructions.
- Key files: `docs/architecture.md`, `docs/concepts.md`, `docs/control.md`, `docs/events.md`, `docs/storage.md`, `docs/capabilities.md`, `docs/providers.md`, `docs/delegation.md`, `docs/bundles.md`.
- Subdirectories: None; intentionally flat and linked from `docs/README.md`.

**`examples/`:**

- Purpose: Show the installed Python API without duplicating runtime logic.
- Contains: `examples/governed_coding.py`, a thin argument-parsing wrapper over `openrund.demo.run_governed_coding_demo`, and `examples/README.md`.
- Treatment: Essential documentation code; keep the workflow implementation in `src/openrund/demo.py`.

**`.planning/`:**

- Purpose: GSD project state, roadmap history, audits, plans, summaries, and generated codebase maps.
- Contains: Current top-level state documents, `.planning/codebase/`, milestone archives, and an empty current `.planning/phases/` directory.
- Key files: `.planning/PROJECT.md`, `.planning/ROADMAP.md`, `.planning/STATE.md`, `.planning/MILESTONES.md`.
- Subdirectories: `.planning/milestones/v1.3-phases/` and `.planning/milestones/v2.0-phases/` preserve completed implementation evidence; `.planning/milestones/project-history/` preserves older maps, quick tasks, research, and docs refreshes.
- Treatment: Historical/workflow data. It may be archived outside the runtime repository only through an explicit GSD/history decision, not opportunistically deleted.

## Source Package Details

**`src/openrund/contracts/`:**

- `commands.py`: Operations, decisions, traces, decision records, `Command`, and `CommandResult`.
- `events.py`: Event catalog, payload types, actors, and runtime Event union.
- `runs.py`: Run lifecycle, waits, governance, delegation, Artifacts, and completion requirements.
- `content.py`: Content, mutations, effects, evidence, and Artifact references.
- `capabilities.py`: Capability definitions, transports, reliability, cancellation, and results.
- `ids.py`, `time.py`, `json.py`, `portable.py`: Primitive validated values shared by the larger contracts.
- `__init__.py`: Intentionally does not flatten the entire kernel; callers import domain modules explicitly.

**`src/openrund/engine/`:**

- `_engine.py`: Authoritative full-history submit/retry/atomic-append pipeline.
- `_legality.py`: Central lifecycle and completion-readiness decision evaluation.
- `_governance.py`: Capability, policy, root, evidence, and schema governance.
- `_coordination.py`: Wait and recovery legality.
- `_delegation.py`: Parent/child handoff, join, cancellation, and atomic batches.
- `_events.py`: Event-intent materialization.
- `_records.py`: Durable command-decision records.
- `_proposals.py`: Converts inert model proposals to Commands.
- `_model.py`: Injected Engine dependencies.

**`src/openrund/views/`:**

- `_history.py`: Exact watermark and sequence validation.
- `_rebuild.py`: One-pass composition of all View reducers.
- `_model.py`: Complete/incomplete replay contracts and aggregate bundle.
- `_actions.py`, `_artifacts.py`, `_waits.py`, `_run_status.py`, `_delegation.py`, `_checkpoints.py`, `_reports.py`, `_timeline.py`: Focused deterministic projections.

**`src/openrund/storage/`:**

- `_database.py`: SQLite versioning, schema validation, WAL/FULL durability, transaction and error translation.
- `_events.py`: `SqliteRunEventStore`, including atomic multi-run append.
- `_artifacts.py`: Artifact metadata/blob custody and recovery.
- `_leases.py`: Execution lease adapter.
- `_event_log.py`: Advisory ordered post-commit subscribers.
- `_layout.py`: Secure deterministic per-run directory layout.

**`src/openrund/capabilities/`:**

- `_registry.py`: Declaration/binding validation, schema enforcement, and route resolution.
- `_runner.py`: Durable start, dispatch, Artifact custody, and terminal/unknown recording.
- `_transports.py`: In-process and strict one-request stdio JSON-RPC transports.
- `_sandbox.py`: Named filesystem mounts and containment checks.
- `filesystem.py`, `documents.py`, `process.py`, `git.py`: Built-in Capability declarations and handlers.
- `documents_worker.py`: Subprocess worker entry point, separate from the parent-side declaration by design.

**`src/openrund/providers/`:**

- `_http.py`: Async HTTP protocol, stdlib transport, response and SSE parsing.
- `_normalization.py`: Provider-neutral tool declarations and inert proposal construction.
- `openai.py`: OpenAI Responses plus local OpenAI-compatible provider.
- `anthropic.py`: Anthropic Messages provider.

**`src/openrund/bundles/`:**

- `_model.py`: Manifest, commitments, completeness, Artifacts, verification, and resume contracts.
- `_wire.py`, `_hashing.py`, `_compatibility.py`: Canonical Bundle bytes and compatibility rules.
- `_export.py`, `_importing.py`, `_verify.py`, `_replay.py`, `_resume.py`: Lifecycle operations over `.orun` directories.
- `_paths.py`: Hostile-tree path validation.
- `_render.py`: Deterministic human- and machine-readable evidence exports.

**`src/openrund/assembly/`, `src/openrund/operator/`, and `src/openrund/runtime/`:**

- `assembly/_factory.py`: Builds the SQLite stores, governance context, Engine, Capability registry, runners, operator, and optional provider loop.
- `assembly/_model.py`: Validated config and resource-owning `LocalRuntime`.
- `operator/_service.py`: Operational read/write use cases over canonical history.
- `operator/_render.py`: Stable text and JSON presentation.
- `runtime/_loop.py`: Resource-bounded durable model-call coordinator.

## Naming Conventions

**Files:**

- `snake_case.py`: All Python modules, for example `src/openrund/views/_run_status.py`.
- `_private.py`: Package-private implementation module exposed selectively through `__init__.py`.
- `test_<subject>.py`: Pytest modules, for example `tests/engine/test_legality.py`.
- `UPPERCASE.md`: Repository-level policy and product documents such as `README.md` and `SECURITY.md`.
- `lowercase.md`: Topic documentation under `docs/`.
- `*.jsonl`: Frozen one-case compatibility evidence under `tests/fixtures/compatibility/v1/evidence/`.

**Types and Functions:**

- `PascalCase`: Public and private classes, enums, protocols, and dataclasses.
- `snake_case`: Functions, methods, fields, and local variables.
- `_leading_underscore`: Private helpers and modules.
- `ALL_CAPS`: Module constants and fixed wire/schema limits.
- Error codes: Lowercase `snake_case` strings carried by typed exceptions.

**Directories:**

- Lowercase package/domain names: `contracts/`, `engine/`, `views/`, `storage/`.
- Test directories mirror source package names.
- Milestone phase directories use numeric kebab-case names, for example `.planning/milestones/v2.0-phases/31-engine-authority-and-core-run-semantics/`.

**Special Patterns:**

- `__init__.py`: Explicit supported package exports; not a wildcard aggregation convention.
- `__main__.py`: Module execution entry.
- `py.typed`: Marker that shipped inline type information is supported.
- `conftest.py`: Area-scoped pytest fixtures.
- `MISSING`: Sentinel used where absent and explicit null have different semantics.

## Where to Add New Code

**New Domain Concept or Lifecycle Operation:**

- Contracts: The focused module under `src/openrund/contracts/`.
- Wire support: `src/openrund/codec/` if serialized.
- Authority: `src/openrund/engine/_legality.py`, `src/openrund/engine/_events.py`, and related focused coordination/governance module.
- Projection: A focused reducer under `src/openrund/views/` and composition in `src/openrund/views/_rebuild.py`.
- Tests: Mirrored modules under `tests/contracts/`, `tests/codec/`, `tests/engine/`, and `tests/views/`.
- Compatibility: Versioned evidence under `tests/fixtures/compatibility/`; do not mutate v1 casually.

**New Storage Adapter:**

- Protocol: Extend the narrow port in `src/openrund/ports/` only if the semantic interface changes.
- Implementation: Add a focused module under `src/openrund/storage/` or a separate adapter package.
- Assembly: Wire it explicitly in `src/openrund/assembly/_factory.py` or a new host-owned composition root.
- Tests: `tests/storage/`, including concurrency and failure translation.

**New Capability:**

- Contract reuse: `src/openrund/contracts/capabilities.py`.
- Built-in implementation: `src/openrund/capabilities/<name>.py` with a declaration and transport bindings.
- External worker: A separate worker entry module only when process isolation/transport proves the boundary.
- Assembly: Register only through explicit `LocalAssemblyConfig` behavior in `src/openrund/assembly/`.
- Tests: `tests/capabilities/test_<name>.py`, including sandbox and transport failure cases.

**New Provider:**

- Shared normalization: `src/openrund/providers/_normalization.py`.
- HTTP plumbing: Reuse `src/openrund/providers/_http.py`.
- Adapter: `src/openrund/providers/<provider>.py` implementing the `ModelProvider` protocol.
- Public export: `src/openrund/providers/__init__.py` and, only if intended, `src/openrund/__init__.py`.
- Tests: `tests/providers/test_<provider>.py` plus compatibility evidence if normalization is externally frozen.

**New CLI or Operator Command:**

- Typed use case: `src/openrund/operator/_service.py` or a focused operator module if the service would become less cohesive.
- Routing/options: `src/openrund/cli.py`.
- Rendering: `src/openrund/operator/_render.py` and result models in `src/openrund/operator/_model.py`.
- Tests: `tests/operator/` and `tests/cli/`.

**New Bundle Field or Export:**

- Model: `src/openrund/bundles/_model.py`.
- Canonical wire/hash: `src/openrund/bundles/_wire.py` and `src/openrund/bundles/_hashing.py`.
- Lifecycle: The focused export/import/verify/replay module.
- Tests: `tests/bundles/`, including hostile input, hygiene, and integration tests.
- Compatibility: Update only through an explicit versioning/compatibility decision.

**Utilities:**

- Keep helpers inside the package that owns their trust boundary.
- Put cross-domain value types in `src/openrund/contracts/` only when they are genuinely domain contracts.
- Avoid a generic `utils.py`; existing path, codec, storage, Bundle, and sandbox helpers intentionally encode different security rules.

## Safe Structural Simplifications

| Opportunity | Evidence | Safe boundary |
| --- | --- | --- |
| Remove `.venv 2/` | It is empty, untracked, and not the configured `.venv` symlink. | Confirm no external IDE task references the spaced path; no source change is required. |
| Discard duplicate `dist/.gitignore 2` with build output | `dist/` is ignored and fully reconstructable; both ignore files are one byte. | Remove only as part of clearing/rebuilding `dist/`, never promote it to tracked source. |
| Archive old `.planning/` evidence externally | Completed phase trees live under `.planning/milestones/v1.3-phases/` and `.planning/milestones/v2.0-phases/`; runtime packaging excludes them. | Preserve Git/GSD traceability and current top-level state; this is a repository-history decision, not runtime cleanup. |
| Rename `assembly/_factories.py` | It sits beside `assembly/_factory.py` but owns IDs/clocks rather than graph construction. | Private file rename plus unchanged facade exports and assembly tests. |
| Publish required View fact types | Engine and Operator import several `openrund.views._*` modules directly. | Re-export existing immutable types; do not add another service layer or alter replay. |
| Neutralize provider shared helpers | Anthropic imports `_content_context`, `_decode_object`, `_text`, and `_wire` from the OpenAI adapter. | Move identical helpers to a private provider-neutral module and retain provider corpus behavior. |

No whole runtime package is a safe deletion candidate. The source tree already separates
the contract kernel, authority, projections, ports, adapters, composition, and tests at
useful domain boundaries. The safest reductions are local cleanup and dependency-seam
clarification, not package flattening.

- Committed: Yes; essential and verified by fixture-integrity tests.
