# Requirements: OpenRund v1.2 260513-ontology-governance-audit

**Defined:** 2026-05-13
**Core Value:** Provide a minimal but authoritative runtime where long-running agent runs remain durable, lawful, replayable, resumable, portable, and inspectable even when models, workers, or infrastructure fail.

## v1.2 Requirements

### Discovery And Mapping

- [x] **MAP-01**: `CODEBASE_MAP.md` maps core types, runtime engine, command evaluation, stores, Views, capabilities, providers, CLI, examples, tests, bundles, approval, reconciliation, completion legality, and delegation with per-package authority flags. Completed in Phase 11.
- [x] **MAP-02**: Suspicious authority paths are flagged with concrete file references before any patches are planned. Completed in Phase 11.
- [x] **MAP-03**: Competitor positioning is scoped to Temporal, Kitaru, Microsoft Agent Framework/AGT, OpenAI Agents SDK, and LangChain Deep Agents without turning the milestone into market copy. Completed in Phase 11.

### Ontology And Secondary Surfaces

- [x] **ONTO-01**: `ONTOLOGY_AUDIT.md` maps every core ontology concept to canonical types, Events, lifecycle owner, public API surfaces, CLI surfaces, tests, and violations. Completed in Phase 12.
- [x] **ONTO-02**: Exported semantic names, public APIs, CLI-facing names, event names, View names, receipts, reports, bundles, and examples avoid unapproved root concepts and authority-confusing nouns. Audit completed in Phase 12; critical public naming fixes implemented in Phase 18; guard hardening completed in Phase 19.
- [x] **SURF-01**: `SECONDARY_SURFACE_AUDIT.md` proves receipts, reports, summaries, manifests, assessments, indexes, readiness Views, timeline Views, CLI renderers, and example printouts are derived from Events and Artifacts. Completed in Phase 13.
- [x] **SURF-02**: CLI/demo text does not invent authoritative fields such as `receiptID`, `receiptIdentity`, `gateExplanation`, `outcomeExplanation`, or demo-only summary semantics. Completed in Phase 13.

### Command Path And Governance

- [x] **CMD-01**: `COMMAND_PATH_AUDIT.md` traces every required mutation path and records origin, operation type, Command creation, legality validator, Event appender, emitted Events, bypass risk, and tests. Completed in Phase 14.
- [x] **CMD-02**: All material state-changing non-model paths either enter a visible Engine-owned Command path or are documented as critical gaps with targeted patch tasks. Completed in Phase 14; critical runtime paths patched in Phase 18.
- [x] **GOV-01**: `GOVERNANCE_REALITY_AUDIT.md` proves illegal operation rejection from Command/Event data, including no target Action lifecycle Events and no filesystem mutation. Completed in Phase 15.
- [x] **GOV-02**: Approval deferral and approval resume are proved as separate Command-owned paths with Wait resolution, input capture, schema/Authority/resource revalidation, and Action Events only after accepted resume. Completed in Phase 15; targeted tests completed in Phase 19.
- [x] **GOV-03**: Unknown outcomes block completion when required, reconciliation requires Command/evidence linkage, and completion becomes legal only after reconciliation. Completed in Phase 15; unknown marking Command ownership implemented in Phase 18 and tested in Phase 19.
- [x] **GOV-04**: Completion legality is enforced by runtime contracts and separates semantic Checks from diagnostic Checks. Completed in Phase 15; terminal fallback patched in Phase 18.
- [x] **GOV-05**: Bundle verification proves manifest, layout, file integrity, Event hash chain, Artifact manifest consistency, fail-closed metadata handling, and import-without-auto-resume. Completed in Phase 15; Event hash-chain corruption test hardening completed in Phase 19.

### CLI, Docs, Patches, And Tests

- [x] **CLI-01**: `CLI_SURFACE_AUDIT.md` maps `openrund inspect`, `waits`, `waits show`, `waits resolve`, `actions reconcile`, `replay`, `timeline`, `checks export`, `artifacts show`, `orun export/verify/import/resume-report/replay`, and `pnpm demo:governed-coding-run` to source objects and canonical concepts. Completed in Phase 16.
- [x] **CLI-02**: CLI commands render explanations but do not decide explanations or legality. Completed in Phase 16; inherited runtime command-path gaps were patched in Phase 18 and tested in Phase 19.
- [x] **DOCGAP-01**: `DOC_CODE_GAP_REPORT.md` compares the semantic docs to code reality and classifies each material mismatch by severity, impact, implementation status, and follow-up need. Completed in Phase 17.
- [x] **PATCH-01**: `PATCH_PLAN.md` is written before code changes and requires semantic violations, related naming, and related documentation to be corrected together, with tests proving the corrected semantics. Completed in Phase 18.
- [x] **TEST-01**: `TEST_PLAN.md` lists required existing commands plus targeted tests for provider/worker authority, approval revalidation, deferred Actions, visible approval resume Command path, unknown outcomes, reconciliation evidence, diagnostic Checks, bundle hash-chain corruption, and CLI invented fields.
- [x] **SUM-01**: `SUMMARY.md` gives an honest verdict: governance is real, partially real, or theater, with remaining risks and follow-up tasks. Completed in Phase 20.

## Future Requirements

### Post-Audit Hardening

- **HARDEN-01**: Any unresolved medium or lower semantic gap from v1.2 receives a scoped follow-up phase or issue after critical gaps are closed.
- **HARDEN-02**: Competitor positioning becomes documentation only after code and tests support the differentiated claim.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Hosted control plane | This milestone audits local runtime semantics and public surfaces. |
| Broad new capability catalog | Capability breadth would distract from authority and ontology proof. |
| Marketing site or launch copy | Competitor analysis is used only to sharpen runtime claims. |
| Large refactor for aesthetics | Patches must be the minimum needed to preserve semantics. |
