# Requirements Archive: OpenRund v1.1 Runtime Hardening And Governance Cutover

**Archived:** 2026-05-13
**Archive mode:** reconstructed from phase summaries and current project state.
**Note:** Active `.planning/REQUIREMENTS.md` already describes v1.2 and is preserved.

## Requirement Outcomes

### Codebase Hygiene

- [x] **HYGIENE-01**: Repository residue, demo residue, generated outputs, config drift, SQLite warnings, and deferred phase owners were audited.
- [x] **HYGIENE-02**: Safe residue and ignored config drift were removed from the local baseline.
- [x] **HYGIENE-03**: `pnpm hygiene` was added as a deterministic source-controlled hygiene gate.
- [x] **HYGIENE-04**: SQLite warning posture was traced and documented as an accepted MVP storage-runtime limitation.

### SDK And Runtime Surface

- [x] **SDK-01**: Canonical model/runtime boundary moved to `ModelCall` and `command.recorded` audit facts.
- [x] **SDK-02**: Public provider, storage, capability, and local runtime assembly entry points were exposed.
- [x] **SDK-03**: Examples consume grouped public SDK surfaces instead of concrete internals.
- [x] **SDK-04**: Runtime validation and public docs align around canonical model-call semantics.
- [x] **SDK-05**: Public API guards protect the canonical SDK/runtime surface.
- [x] **SDK-06**: Demo-minimality gaps were deferred from Phase 7 and closed in Phase 10.

### Portability And Replay

- [x] **ORUN-01**: Bundle manifest and export layout carry source Run identity, export profile, critical fields, artifact availability, event integrity, and bundle integrity.
- [x] **ORUN-02**: Bundle verification fails closed on malformed, incomplete, incompatible, or tampered bundles.
- [x] **ORUN-03**: Bundle replay is pure and does not call providers, capabilities, workspaces, or repair logic.
- [x] **ORUN-04**: Bundle import creates explicit custody records under runtime home without implying resumability.
- [x] **ORUN-05**: Resume assessment reports schema, root mapping, capability, provider, policy, Wait, Artifact, terminal-state, and completeness Issues.
- [x] **ORUN-06**: Bundle and resume behavior is covered by runtime tests.

### Coding Agent Substrate

- [x] **SUBSTRATE-01**: Action mutation and observed effects are separated.
- [x] **SUBSTRATE-02**: Action Receipts are deterministic derived surfaces.
- [x] **SUBSTRATE-03**: Workspace-bounded process execution returns artifact-backed stdout/stderr and unknown outcome evidence.
- [x] **SUBSTRATE-04**: Git diff/status behavior is available through a governed capability.
- [x] **SUBSTRATE-05**: The runtime supports coding-agent substrate needs without becoming a coding product.

### Ontology And Public Surface

- [x] **CLEAN-01**: Canonical ontology names are the production surface.
- [x] **CLEAN-02**: View package and imports use canonical View naming.
- [x] **CLEAN-03**: Runtime Command paths and Authority boundaries were migrated.
- [x] **CLEAN-04**: CLI, docs, examples, tests, and public exports use canonical terminology.
- [x] **CLEAN-05**: Static hygiene checks enforce ontology and secondary-surface rules.
- [x] **CLEAN-06**: Secondary surfaces use approved suffixes and remain derived.
- [x] **CLEAN-07**: Legacy demo and documentation surfaces were removed or archived.
- [x] **CLEAN-08**: Pre-canonical run/view/check names and related old names were removed from production semantic surfaces.
- [x] **CLEAN-09**: Public docs were synchronized to the canonical ontology.
- [x] **CLEAN-10**: Phase 9 and Phase 10 plans were realigned to the canonical runtime surface.

### Controlled Runtime Semantics

- [x] **CONTROL-01**: Governance is documented as runtime semantics, not external orchestration glue.
- [x] **CONTROL-02**: `CommandDecision`, `CommandDecisionTraceEntry`, and `LegalityCriterion` describe accepted, rejected, deferred, and superseded outcomes.
- [x] **CONTROL-03**: Model-originated Commands record structured decision traces.
- [x] **CONTROL-04**: CLI explanation surfaces are constrained to runtime-provided facts.

### CLI And Operator Experience

- [x] **CLI-01**: `commands explain` renders persisted Command decision facts.
- [x] **CLI-02**: `actions receipt` renders deterministic Action Receipt data.
- [x] **CLI-03**: `runs readiness` renders completion readiness from Views.
- [x] **CLI-04**: Approval Wait display/resolution and Action reconciliation remain runtime API paths.
- [x] **CLI-05**: Bundle commands are exercised through the built executable.
- [x] **CLI-06**: CLI docs explain the authority boundary and avoid making CLI an authority source.

### Demo, Documentation, And Package Readiness

- [x] **DOCS-01**: Public docs point to the single flagship governed coding demo.
- [x] **DOCS-02**: Quickstart and README use governance-first positioning.
- [x] **DOCS-03**: Demo docs describe rejected, deferred, resumed, reconciled, checked, and bundled proof points.
- [x] **DOCS-04**: Docs link checks pass.
- [x] **PKG-01**: Root package metadata and demo scripts are present.
- [x] **PKG-02**: `pnpm package:check` validates package content.
- [x] **PKG-03**: Contributor setup and release-readiness guidance are present.
