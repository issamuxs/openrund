# Requirements: OpenRund v1.3 Codebase Map Remediation and Hardening

**Defined:** 2026-05-15
**Core Value:** Provide a minimal but authoritative runtime where long-running agent runs remain durable, lawful, replayable, resumable, portable, and inspectable even when models, workers, or infrastructure fail.

## v1.3 Requirements

Requirements for this milestone are derived from the refreshed codebase map in `.planning/codebase/`.

### Security

- [x] **SEC-01**: Stdio JSON-RPC workers receive a minimal explicit environment by default.
- [x] **SEC-02**: Provider HTTP error reporting redacts authorization-looking values and sensitive response details.
- [x] **SEC-03**: Bundle verification rejects absolute, parent-traversal, and platform-escape manifest paths before filesystem access.
- [x] **SEC-04**: Filesystem read-only mount posture blocks write, update, delete, and move inside the capability itself.

### Durability

- [x] **DUR-01**: Event subscriber failures cannot make an already-persisted append appear safely retryable without explicit semantics.
- [x] **DUR-02**: SQLite artifact blob and metadata writes have tested cleanup or recovery behavior for partial failures.
- [x] **DUR-03**: Delegation parent/child append sequences have tested partial-failure behavior or repair semantics.

### Hygiene

- [x] **HYG-01**: Generated `.js`, `.d.ts`, and source map files are removed from `packages/*/src` where inappropriate.
- [x] **HYG-02**: Hygiene checks reject future generated build artifacts in source directories.
- [x] **HYG-03**: Python document worker setup is documented or scripted for fresh workspace verification.

### Maintainability

- [x] **MAINT-01**: Provider operation normalization is shared or otherwise made parity-tested across OpenAI, Anthropic, and local adapters.
- [x] **MAINT-02**: Filesystem duplicate implementations are consolidated or covered by explicit parity tests.
- [x] **MAINT-03**: High-risk monolith seams are split only where the Engine authority boundary and public exports remain stable.

### Performance

- [x] **PERF-01**: Process and git capabilities avoid unbounded stdout and stderr buffering for large outputs.
- [x] **PERF-02**: View and event replay pressure has a scoped improvement path, such as snapshots or targeted read APIs.
- [x] **PERF-03**: Bundle import hashing avoids unnecessary whole-directory reads when manifest integrity is sufficient.

### Verification

- [x] **TEST-01**: High-priority findings from `.planning/codebase/CONCERNS.md` have focused Vitest or pytest coverage.
- [x] **TEST-02**: Provider live-contract drift has a documented CI or local verification path without making normal tests require secrets.
- [x] **TEST-03**: New tests follow `.planning/codebase/TESTING.md` patterns: real temp files or SQLite where appropriate, provider `fetchImpl` mocks, and no mocked runtime authority.

## Future Requirements

### Scaling

- **SCALE-01**: Add a server-grade event store with distributed leases, snapshots, streaming reads, and object storage integration.
- **SCALE-02**: Replace wall-clock-only lease expiry with database/server time or monotonic lease fencing for multi-host workers.

### Operations

- **OPS-01**: Add hosted CI pipelines for scheduled live provider contract checks.
- **OPS-02**: Add production observability integrations once runtime semantics remain stable under local verification.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Hosted multi-tenant control plane | Deferred until local runtime semantics are stronger. |
| Distributed coordination and HA | Requires server-grade storage and lease semantics beyond this remediation milestone. |
| Broad production capability catalog | The milestone is remediation and hardening, not expansion of capability surface area. |
| Rich operator UI | The current need is runtime correctness, package hygiene, and developer-facing verification. |
| Full `RuntimeEngine` rewrite | Refactors must preserve authority semantics and should be limited to seams required by the mapped concerns. |
