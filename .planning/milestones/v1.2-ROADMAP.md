## Original Roadmap

## Overview

This milestone audits whether OpenRund's strongest claim is true in code:

> Model output is untrusted input. The Engine controls what becomes Run history.

The work starts with discovery and code-referenced audits, then patches only the semantic gaps required to make the MVP governance model real. The comparison set is Temporal, Kitaru, Microsoft Agent Framework/AGT, OpenAI Agents SDK, and LangChain Deep Agents, but competitor research is used only to sharpen the falsifiable runtime claim.

## Phase Details

### Phase 11: Codebase And Competitor Discovery

**Goal:** Produce `CODEBASE_MAP.md` and scoped competitor notes that identify where OpenRund must prove differentiated runtime governance.
**Mode:** audit
**Depends on:** v1.1 completion and refreshed `.planning/codebase/`
**Requirements:** MAP-01, MAP-02, MAP-03
**Success Criteria:**
1. Every implementation area is mapped with responsibility, public exports, Event-writing, Command-creation, legality, View mutation, and risk notes.
2. Suspicious Event append paths are flagged before patches.
3. Competitor notes distinguish durable execution, long-running agent runtime, enterprise agent framework/governance toolkit behavior, agent SDK guardrails, and deep-agent harness behavior from OpenRund's Engine-owned Command path.

**Status note:** Completed 2026-05-13. Phase 11 refreshed `CODEBASE_MAP.md`, flagged suspicious authority paths, and added scoped competitor comparison notes.

### Phase 12: Ontology Audit

**Goal:** Produce `ONTOLOGY_AUDIT.md` and identify public semantic naming violations.
**Mode:** audit
**Depends on:** Phase 11
**Requirements:** ONTO-01, ONTO-02
**Success Criteria:**
1. Each core concept maps to canonical types, Events, lifecycle owner, public API, CLI output, and tests.
2. Banned or authority-confusing exported names are classified as violation, acceptable implementation-local generic type, or follow-up debt.
3. Rename candidates are scoped before implementation.

**Status note:** Completed 2026-05-13. Phase 12 found public ontology debt in `CommandDecisionRecord`, `EffectRecord`, checkpoint `retainedFacts`, `LeaseRecord`, `ArtifactRecord`, and public docs `Boundary` headings; no code renames were made.

### Phase 13: Secondary Surface Audit

**Goal:** Produce `SECONDARY_SURFACE_AUDIT.md` and prove derived surfaces stay derived.
**Mode:** audit
**Depends on:** Phase 12
**Requirements:** SURF-01, SURF-02
**Success Criteria:**
1. Receipts, reports, manifests, assessments, indexes, summaries, readiness Views, and timeline Views point back to Events and Artifacts.
2. CLI and demo output do not expose fake IDs or fake lifecycle concepts.
3. Any invented explanatory field becomes a patch candidate or documented debt.

**Status note:** Completed 2026-05-13. Phase 13 found no CLI/demo fake fields and confirmed secondary surfaces are derived, while carrying `retainedFacts`, `EffectRecord`, and command-path proof to later phases.

### Phase 14: Command Path Audit

**Goal:** Produce `COMMAND_PATH_AUDIT.md` and classify every mutation path against the preferred authority shape.
**Mode:** audit
**Depends on:** Phase 13
**Requirements:** CMD-01, CMD-02
**Success Criteria:**
1. Required paths from `recordModelOutput` through bundle import/resume assessment are traced with file references.
2. Paths that append authoritative Events without a visible Command are marked critical unless intentionally bootstrap/internal and documented.
3. Test coverage is mapped to each path.

**Status note:** Completed 2026-05-13. Phase 14 found critical non-model bypasses around raw append, interactions, timers, Check recording, unknown-outcome marking, delegated handoff/cancellation, and fallback terminal Events.

### Phase 15: Governance Reality Audit

**Goal:** Produce `GOVERNANCE_REALITY_AUDIT.md` and prove governance is enforced by code and tests.
**Mode:** audit
**Depends on:** Phase 14
**Requirements:** GOV-01, GOV-02, GOV-03, GOV-04, GOV-05
**Success Criteria:**
1. Illegal filesystem mutation rejection has Command trace proof, no Action lifecycle Events, and no file write.
2. Approval deferral and resume are separate, visible, revalidated runtime paths.
3. Unknown outcomes block completion until evidence-backed reconciliation.
4. Completion legality is enforced by runtime contracts, not demo output.
5. Bundle verification fails closed on manifest, layout, integrity, Event hash-chain, Artifact manifest, and schema defects.

**Status note:** Completed 2026-05-13. Phase 15 verdict: governance is partially real. Core model-path governance is implemented; non-model Command bypasses and targeted test gaps remain.

### Phase 16: CLI Surface Audit

**Goal:** Produce `CLI_SURFACE_AUDIT.md` and harden CLI explanation boundaries.
**Mode:** audit
**Depends on:** Phase 15
**Requirements:** CLI-01, CLI-02
**Success Criteria:**
1. Every listed CLI command maps to a source object/View and canonical concept.
2. CLI surfaces render but do not decide legality or explanation.
3. `pnpm demo:governed-coding-run` output contains no invented runtime fields.

**Status note:** Completed 2026-05-13. Phase 16 found CLI renderers are derived and mutating CLI commands delegate to runtime; remaining risk is inherited from runtime command-path gaps, not CLI-specific fake concepts.

### Phase 17: Doc/Code Gap Report

**Goal:** Produce `DOC_CODE_GAP_REPORT.md`.
**Mode:** audit
**Depends on:** Phase 16
**Requirements:** DOCGAP-01
**Success Criteria:**
1. Claims from `docs/concepts.md`, `docs/architecture.md`, `docs/control.md`, `docs/capabilities.md`, `docs/events.md`, `docs/delegation.md`, `docs/bundles.md`, `docs/api.md`, `docs/storage.md`, and `docs/providers.md` are compared to code reality.
2. Each gap has severity, user-facing impact, recommended fix, implementation status, and follow-up status.

**Status note:** Completed 2026-05-13. Phase 17 found the docs describe the right target contract but overclaim current uniform Command ownership, public append safety, Check recording ownership, and terminal fallback closure.

### Phase 18: Patch Plan And Semantic Fixes

**Goal:** Produce `PATCH_PLAN.md` before coding and implement the minimum critical fixes.
**Mode:** standard
**Depends on:** Phase 17
**Requirements:** PATCH-01
**Success Criteria:**
1. Semantic violations are corrected, as well as related naming and documentation.
2. Every patch lists problem, files, semantic effect, tests, and risk.
3. Fixes are narrow enough to preserve MVP behavior while making the authority model true.

**Status note:** Completed 2026-05-14. Phase 18 added Command ownership to critical non-model runtime mutations, added runtime-owned Check recording, closed terminal fallback Events, corrected public ontology names, and updated related docs.

### Phase 19: Governance Test Hardening

**Goal:** Produce `TEST_PLAN.md` and run required verification.
**Mode:** standard
**Depends on:** Phase 18
**Requirements:** TEST-01
**Success Criteria:**
1. Targeted tests prove provider/worker non-authority, approval revalidation, deferred Action behavior, approval resume Command path, unknown-outcome blocking, reconciliation evidence, diagnostic Check separation, bundle hash-chain failure, and CLI field discipline.
2. Required commands are run or failures are documented with exact cause.

### Phase 20: Milestone Verdict

**Goal:** Produce `SUMMARY.md` with a blunt verdict.
**Mode:** audit
**Depends on:** Phase 19
**Requirements:** SUM-01
**Success Criteria:**
1. The summary lists what was audited, critical findings, patches, tests, remaining risks, and follow-up tasks.
2. Verdict is one of: governance is real, partially real, or theater.

**Status note:** Completed 2026-05-15. Phase 20 replaced the launch summary with the final scoped verdict: governance is real for the audited MVP runtime paths and public surfaces, with explicit residual risks.
