# Plan 25-01: Performance Pressure Relief

## Objective

Relieve the largest local-runtime memory and hashing pressure points without changing durable replay semantics.

## Threat Model

<threat_model>

**Assets protected:**
- Runtime memory under large process/git output.
- Bundle import provenance.
- Replay-as-source-of-truth semantics.

**Threats:**
- Medium: process and git capabilities buffer unbounded stdout/stderr in memory.
- Medium: bundle import re-reads all files after verification already hashed manifest-declared content.
- Low: view rebuild pressure is real but unsafe to patch casually without a snapshot freshness contract.

**Mitigations required:**
- Captured process/git artifact bytes are bounded and marked truncated.
- Full-stream hashes remain available for output identity.
- Bundle import reuses verified manifest bundle integrity.
- View snapshot work is explicitly deferred with rationale.

</threat_model>

## Tasks

<task id="PERF-01">
<title>Bound process and git output capture</title>
<read_first>
- `packages/capability-process/src/process-capability.ts`
- `packages/capability-git/src/git-capability.ts`
- `tests/capabilities/process.test.ts`
- `tests/capabilities/git.test.ts`
</read_first>
<action>
Introduce bounded output capture for stdout and stderr. Preserve full-stream SHA-256 hashes by hashing chunks as they arrive, but only retain up to a configured byte limit for previews and inline artifacts. Add truncation metadata to outputs and artifact metadata.
</action>
<acceptance_criteria>
- Process capability accepts a `maxOutputBytes` option and marks truncated stdout/stderr.
- Git capability accepts a `maxOutputBytes` option and marks truncated stdout/stderr.
- Tests prove large outputs are bounded.
</acceptance_criteria>
</task>
