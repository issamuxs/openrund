# Plan 23-01: Source Hygiene And Developer Setup

## Objective

Remove generated-source drift and make fresh workspace verification less fragile without changing runtime package boundaries.

## Threat Model

<threat_model>

**Assets protected:**
- TypeScript source directories as authoritative source, not generated output.
- Fresh workspace verification commands.
- Python documents worker capability boundary.

**Threats:**
- Medium: stale ignored `src/*.js` artifacts shadow edited `.ts` files in test/runtime resolution.
- Medium: hygiene misses ignored generated artifacts because it only checks tracked and non-ignored untracked paths.
- Medium: fresh developers run root checks but miss Python worker dependencies and tests.

**Mitigations required:**
- Generated source-side artifacts are absent from `packages/*/src`.
- Hygiene scans source directories directly for generated artifacts.
- Root developer docs or scripts cover Python worker setup and tests.

</threat_model>

## Tasks

<task id="HYG-01">
<title>Remove source-side generated artifacts</title>
<read_first>
- `.planning/codebase/CONCERNS.md`
- `packages/storage-sqlite/src`
</read_first>
<action>
Ensure generated `.js`, `.js.map`, `.d.ts`, and `.d.ts.map` files are absent from package source directories. Keep build output under package `dist/`.
</action>
<acceptance_criteria>
- No `packages/*/src/**/*.js`, `*.js.map`, `*.d.ts`, or `*.d.ts.map` files remain in the working tree.
- `pnpm test` does not depend on stale source-side generated JavaScript.
</acceptance_criteria>
</task>

<task id="HYG-02">
<title>Make hygiene reject future generated artifacts under source directories</title>
<read_first>
- `scripts/check-hygiene.mjs`
- `tests/public-api/ontology-guards.test.ts`
</read_first>
<action>
Extend `scripts/check-hygiene.mjs` with a direct filesystem scan for generated outputs under `packages/*/src`, including ignored files. Add a public-api regression test that creates a temporary source-side generated artifact, runs the hygiene script, verifies failure, and removes the artifact.
</action>
<acceptance_criteria>
- `pnpm hygiene` fails when `packages/*/src/**/*.js`, `*.js.map`, `*.d.ts`, or `*.d.ts.map` exist.
- A focused Vitest test covers the new hygiene rule.
- Existing ontology and secondary-surface checks still run when no hygiene violations are present.
</acceptance_criteria>
</task>

## Verification

Run:

```bash
pnpm test
pnpm hygiene
pnpm test:python-documents
find packages -path '*/src/*' \( -name '*.js' -o -name '*.js.map' -o -name '*.d.ts' -o -name '*.d.ts.map' \) -type f
```

## Must Haves

- Source-side generated artifacts stay out of package source directories.
- Hygiene catches future drift even for ignored files.
- Python documents worker verification is visible from the root developer flow.
