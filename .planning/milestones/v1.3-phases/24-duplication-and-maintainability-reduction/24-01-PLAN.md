# Plan 24-01: Duplication And Maintainability Reduction

## Objective

Reduce duplicated provider action normalization and make filesystem duplicate behavior visibly parity-checked without changing the Engine authority facade.

## Threat Model

<threat_model>

**Assets protected:**
- Provider adapter consistency.
- Filesystem capability sandbox and posture semantics.
- Runtime Engine authority boundary.

**Threats:**
- Medium: provider adapters diverge on qualified names, malformed JSON arguments, fallback action IDs, or batch construction.
- Medium: built-in and package filesystem implementations diverge silently on mutation posture and sandbox behavior.
- Medium: over-eager monolith extraction could move legality decisions outside `RuntimeEngine`.

**Mitigations required:**
- Shared provider helper owns common action normalization.
- Filesystem duplicate behavior is parity-tested.
- Runtime Engine seam extraction is deferred unless it can preserve the current authority facade.

</threat_model>

## Tasks

<task id="MAINT-01">
<title>Centralize provider action normalization</title>

<action>
Add a shared core helper for qualified provider tool names, safe JSON argument parsing, single action creation, and operation batch creation. Refactor provider adapters to use it while preserving provider-specific response shape handling.

<acceptance_criteria>

- OpenAI and local adapters use the shared JSON argument parser.

</acceptance_criteria>
</task>

</acceptance_criteria>
