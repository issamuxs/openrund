# Ontology Audit

**Analysis date:** 2026-05-13  
**Status:** Phase 12 complete, audit-only
**Scope:** `docs/concepts.md`, core/runtime/views/CLI public surfaces, examples, guard scripts, public API tests.

## Verdict

The core ontology exists in code and is mostly recognizable: `Run`, `Command`, `Event`, `Message`, `ModelCall`, `Action`, `Wait`, `Delegation`, `Check`, `Checkpoint`, `Annotation`, `Artifact`, `Capability`, `Authority`, `Lease`, `Bundle`, and `View` all have concrete implementation anchors.

Post-Phase-18 rerun: the public naming violations found in Phase 12 were corrected in production/public surfaces. `CommandDecisionRecord`, `EffectRecord`, `LeaseRecord`, `ArtifactRecord`, checkpoint `retainedFacts`, and public docs headings using `Boundary` no longer appear in current packages/docs/tests/examples outside historical planning/audit text. The guard now explicitly rejects those old names on current public/production surfaces.

Remaining caveat: this artifact preserves the original Phase 12 findings below for audit traceability. Treat old-name rows as resolved by Phase 18 unless a later section says otherwise.

## Event And Surface Naming

Canonical Event names are clean and align to ontology verbs: `run.*`, `command.recorded`, `message.*`, `annotation.recorded`, `model_call.*`, `action.*`, `wait.*`, `delegation.*`, `check.recorded`, `checkpoint.created`, `artifact.*`, `authority.*`, and `lease.*` in `packages/core/src/events.ts:31` through `packages/core/src/events.ts:69`.

Approved secondary suffixes are used in several public names: `RunStatusView`, `WaitQueueView`, `ActionReceipt`, `ResumeAssessment`, `BundleManifest`, `ResumeAssessmentIssue`, `ArtifactIndexView`, and `TimelineView`.

The main naming gap is not Event grammar. It is exported support vocabulary still using banned nouns (`Record`, `Facts`) and public docs headings still using `Boundary`.
