# Documentation Refresh Replacement Task Set

## Goal

Replace the accumulated `docs/` set with a minimal, current, code-verified documentation set that reflects the canonical ontology and current production names after Phase 8.75.

Do not archive `docs/` first. Keep it live until the replacement set is complete and verified, then replace atomically and archive superseded docs as the final step.

## Observed Problems

- `docs/README.md` still links to deleted `docs/ontology-migration.md`.
- Several docs still describe names as compatibility/current migration surfaces rather than presenting the now-canonical codebase.
- Docs still contain repetitive event-mapping and compatibility prose that should move out of reader-facing material.
- Public API docs must reflect `RuntimeEngine`, `exportBundle`, `verifyBundle`, `defaultBundlePath`, `requireOutputArtifact`, `requireSourceCoverage`, `requireKnownActionOutcomes`, `AuthorityGrant`, `PolicyRule`, `CapabilityResult`, and Bundle vocabulary.
- The docs should be minimal and objective, not a history of how the ontology migration happened.

## Target Documentation Set

Keep only the docs needed for open-source orientation and implementation correctness:

- `docs/README.md`: documentation map and reading order.
- `docs/concepts.md`: locked ontology and secondary-surface doctrine summary.
- `docs/quickstart.md`: smallest local runtime loop using current names.
- `docs/architecture.md`: normative runtime authority, package responsibilities, and control loop.
- `docs/events.md`: event envelope, event grammar, and current event catalog.
- `docs/api.md`: public TypeScript API and CLI surface.
- `docs/capabilities.md`: Capability, Action, Authority, worker result, artifact/effect/evidence rules.
- `docs/bundles.md`: `.orun` Bundle contract. Rename or replace `docs/orun.md`.
- `docs/providers.md`: ModelCall/provider adapter boundary.
- `docs/storage.md`: storage guarantees, runtime home, workspace roots, leases, artifacts.
- `docs/delegation.md`: Delegation and join Wait semantics.
- `docs/contributing.md`: tests, hygiene, naming, documentation rules.

Archive or merge:

- `docs/principles.md`: merge into `concepts.md` and `architecture.md`, then archive.
- `docs/runtime-semantics.md`: merge into `architecture.md`, `api.md`, and `capabilities.md`, then archive.
- `docs/secondary-surfaces.md`: either keep as `docs/contributing.md` section or retain only if it remains concise.
- `docs/orun.md`: rename to `docs/bundles.md` or rewrite in place and update all links.

## Task 1: Code-Verified Documentation Inventory

Produce `.planning/docs-refresh/INVENTORY.md`.

Work:
- List every current public package export from `packages/*/src/index.ts`.
- List every current npm script and demo command from `package.json`.
- List every CLI command from `packages/cli/src/index.ts`.
- List every public runtime helper/type used in examples and tests.
- List every doc link and broken link in `docs/`.
- List stale terminology found in docs.

Acceptance:
- Inventory names current code surfaces exactly.
- No proposed doc claim is introduced without a code source path.

## Task 2: Replacement Outline And Deletion Map

Produce `.planning/docs-refresh/OUTLINE.md`.

Work:
- Define the final doc set and each file's scope.
- Define which old doc content is kept, merged, rewritten, or archived.
- Define a link map from old paths to new paths.
- Define the archive destination: `docs/archive/phase-8.75-pre-refresh/`.

Acceptance:
- Every current `docs/*.md` file has one final disposition.
- No final doc overlaps another doc's authority.

## Task 3: Draft Fresh Docs Outside `docs/`

Create `docs-next/` or `.planning/docs-refresh/draft-docs/`.

Work:
- Draft the final documentation set from the outline.
- Use current code names only.
- Avoid migration-history framing except in an archived note.
- Keep `concepts.md` authoritative and concise.
- Keep `architecture.md` normative and implementation-facing.
- Keep `api.md` concrete and import-oriented.

Acceptance:
- Draft docs have no stale production names.
- Draft docs are readable as a clean first-time OSS documentation set.
- Draft docs include file/API references only when verified against code.

## Task 4: Verification Harness

Update or add documentation checks.

Work:
- Ensure docs link checks cover final docs.
- Extend hygiene to reject stale names in final docs.
- Add a docs/code-reference test for public imports shown in examples.
- Ensure deleted/renamed docs do not remain linked.

Acceptance:
- `pnpm hygiene` fails if stale names re-enter final docs.
- `pnpm test` fails on broken doc links.

## Task 5: Atomic Replacement And Archive

Work:
- Move current docs that are not retained into `docs/archive/phase-8.75-pre-refresh/`.
- Move verified draft docs into `docs/`.
- Update all links in docs, examples, AGENTS.md, and planning references that point to renamed docs.
- Remove `docs-next/` or draft files after replacement.

Acceptance:
- `docs/` contains only the target documentation set plus archive.
- No live doc links point to archived docs except an explicit archive index.
- The archive is clearly marked historical and non-normative.

## Task 6: Final Verification

Run:

- `pnpm typecheck`
- `pnpm test`
- `pnpm hygiene`
- `rg` stale-name scans over `docs/`, `examples/`, `packages/`, `tests/`, and scripts.

Acceptance:
- All commands pass.
- Stale names appear only in `docs/archive/**`, historical fixtures, or scanner patterns.
- Final docs describe the current codebase, not the migration process.
