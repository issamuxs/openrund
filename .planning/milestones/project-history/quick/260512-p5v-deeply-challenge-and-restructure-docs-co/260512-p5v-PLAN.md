# Quick Plan: Deep Ontology Restructure For `docs/concepts.md`

## Goal

Rewrite `docs/concepts.md` as a stricter ontology document rather than a mixed glossary/API guide. The document should challenge hierarchy, symmetry, naming conventions, entity/relationship separation, and request taxonomy.

## Tasks

1. Refactor ontology categories.
   - Remove `Compatibility Helper` as an ontology category.
   - Separate canonical concepts from code symbols, lifecycle event names, operation names, relationship names, derived views, and helper APIs.
   - State naming conventions explicitly: Concept Title Case, Type/API PascalCase, event and operation literals exactly as code uses them.

2. Rebuild the concept hierarchy.
   - Make `Transition Request` the meta concept with `Model Request`, `Input Request`, and `Control Request` as symmetrical variants.
   - Treat lifecycle verbs such as `created`, `added`, `requested`, `started`, `completed`, `resolved`, and `recorded` as event-state verbs, not concept names.
   - Group relationships separately: ownership, causation, correlation, lineage, authority grant, wait blocker, join target set, artifact reference, and projection derivation.

3. Verify against live code and stale vocabulary guards.
   - Check `packages/core/src/model.ts`, `packages/core/src/session.ts`, and `packages/core/src/events.ts`.
   - Run targeted docs/public API tests and stale ontology searches.
