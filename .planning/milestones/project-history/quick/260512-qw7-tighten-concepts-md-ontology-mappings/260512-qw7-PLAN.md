# Quick Plan: Tighten `docs/concepts.md` Ontology Mappings

## Objective

Apply the user's ontology-review comments to `docs/concepts.md` so the locked
concept backbone is deterministic: one concept, one owner, one lifecycle, one
mapping.

## Scope

- Tighten Rule 2 so runtime entities require identity, lifecycle, and
  references, while Bundle and View can remain ontology terms without pretending
  to be live runtime entities.
- Remove the Command/ModelCall ambiguity by making Operations non-authoritative
  until the Engine records Commands.
- Make child Run, Delegation, and join Wait mappings deterministic.
- Choose registry-only Capability semantics for the current minimal ontology.
- Remove Authority/Policy `or` mappings and document policy rules as value
  changes pending a later Authority migration.
- Use exact current child join event literals in the Wait mapping.

## Non-Goals

- Do not change runtime code or persisted event literals.
- Do not modify docs outside `docs/concepts.md` unless tests expose a direct
  documentation consistency break.
