# Strengthen Governed Coding Demo Proof Surfaces - Summary

Date: 2026-05-13

## Outcome

The governed coding demo now surfaces the control proof chain from framework
runtime data instead of demo-local presentation logic.

Implemented:

- Command Events now carry typed Wait linkage for deferred, resolved, and
  resumed control paths: `createdWaitIDs`, `resolvedWaitIDs`, and
  `causalWaitIDs`.
- Command Events now carry `resultEventTypes` alongside result Event IDs for
  CLI explanation without CLI-invented runtime facts.
- Approval Wait resolution records approved-input validation facts.
- Approval resolution records an operator-origin `resolve_approval` Command.
- Continuing an approved Action records a system `resume_approved_action`
  Command with accepted decision, Wait linkage, deferred Command linkage, and
  result Event IDs/types.
- Action reconciliation records a runtime Command, reconciliation evidence,
  note, operator, and unknown Event linkage.
- ActionReceipt exposes unknown/reconciliation details directly from canonical
  Events, including `previousOutcome: "unknown"` and
  `previousEventType: "action.unknown"`.
- RunCompletionReadinessView exposes source coverage, Check classifications,
  output Artifact requirement satisfaction, pending Waits, unresolved unknown
  outcomes, readiness, and Issues.
- Rejected `complete_run` attempts are persisted as rejected Command decisions
  instead of disappearing as thrown-only conflicts.
- Accepted `complete_run` Commands link to `run.completed` via result Event IDs
  and result Event types.
- Bundle verification returns structured verification checks.
- CLI rendering now prints these framework/view fields directly and does not add
  receipt IDs, explanation prose, compact demo summaries, or demo-only runtime
  facts.
- The demo transcript now includes the accepted resume Command between approval
  resolution and Action completion.
